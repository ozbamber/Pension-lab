# AGENTS.md — Pension Lab

הוראות אלה מיועדות לכל Coding Agent שממשיך את הפרויקט.

## 1. עקרונות בסיס

1. שמור על עברית מלאה ו-RTL בכל UI חדש או קיים.
2. אל תשנה הנחות פיננסיות/פנסיוניות או ניסוח רגולטורי ללא הצדקה ברורה ומקור מתאים.
3. אל תציג את המוצר כייעוץ פנסיוני אישי. זהו כלי תכנון/סימולציה.
4. אל תכניס תלות בשרת, חשבון משתמש, DB או שירות בתשלום בלי שהמשתמש ביקש זאת במפורש.
5. שמור על האפשרות להפעיל את האפליקציה כאתר סטטי.
6. `pension-lab-he/` הוא מקור האמת. `pension-lab-he-standalone.html` הוא build output.

## 2. דרישות פונקציונליות שאסור לשבור

- גיל נוכחי וגיל פרישה משתנים.
- יתרה, שכר ושכר מבוטח.
- הפקדות באחוזים או סכום.
- שלבי שכר.
- שלבי תשואה ריאלית/נומינלית.
- אינפלציה.
- הפסקות עבודה.
- דמי ניהול מהפקדה ומהצבירה.
- מקדם קצבה.
- מעבר בין שקלים של היום לשקלים עתידיים.
- גרפי צבירה.
- Explorer לגיל פרישה.
- תרחישים שמרני / בסיס / צמיחה.
- שמירת תרחישים מקומית והשוואה ביניהם.
- תמיכה במובייל ללא overflow אופקי.

## 3. כללי מנוע

- שלב השכר/התשואה האחרון ממשיך לחול גם אחרי הגבול האחרון המוגדר; אין לחזור לשלב הראשון.
- במרווח בין שלבים, התנהגות המנוע חייבת להיות עקבית ומפורשת.
- הפקדות ברוטו, הפקדות נטו, דמי ניהול מהפקדה ודמי ניהול מהצבירה צריכים להיות מופרדים חשבונאית.
- יתרה סופית ופירוק מקורות הצבירה חייבים להיות עקביים חשבונאית.
- יש להגן על קלטים מחוץ לטווח, ערכים לא מספריים ושיעורים לא סבירים.
- שינויים באינפלציה/ריאלי/נומינלי צריכים להיות עקביים בכל תצוגה ולא רק בכרטיס הראשי.

## 4. רגולציה והנחות

- טווח אינפלציה 1%-3% הוא הקשר תכנוני בלבד, לא תחזית.
- אפשרות 30% / 5.15% ריאלי היא מודל אופציונלי בלבד. אין להציג אותה כהנחה שאמורה להישאר זהה לאורך עשרות שנים או כזכאות אחידה לכל משתמש.
- כאשר משנים מידע רגולטורי, עדכן גם את `SOURCES.md` ואת טקסטי האזהרה הרלוונטיים.

## 5. localStorage ופרטיות

- כרגע תרחישים נשמרים מקומית בדפדפן בלבד.
- אין להציג זאת כסנכרון בין מחשבים.
- אם `localStorage` אינו זמין, האפליקציה צריכה להמשיך לפעול עם fallback זמני ולא לקרוס.
- אין לאסוף פרטים מזהים או מידע פיננסי אישי לשרת ללא בקשה מפורשת, תכנון פרטיות והסכמה מתאימה.

## 6. QA חובה לאחר שינוי

לפני מסירה:

1. הרץ את בדיקות המנוע.
2. ודא שאין שגיאות syntax ב-JavaScript.
3. הרץ Browser smoke/QA ב-Chromium כאשר הסביבה מאפשרת זאת.
4. בדוק לפחות viewport דסקטופ ו-mobile (390px בקירוב).
5. ודא שאין overflow אופקי.
6. בדוק save/reset, שינוי גיל פרישה, הפסקת עבודה, real/nominal, Explorer והשוואת תרחישים.
7. אם שינית קוד מקור, בנה מחדש את `pension-lab-he-standalone.html` באמצעות סקריפט ה-build.
8. עדכן `CHANGELOG.md` ו-`QA.md` כאשר השינוי משמעותי.

אם QA מסוים לא בוצע, כתוב זאת במפורש; אל תסמן אותו כעובר.

## 7. Deployment

היעד הנוכחי הוא פרסום ללא עלות, תוך שמירה על אפשרות לצמוח בהמשך.

העדפה נוכחית:

- GitHub repository למקור.
- Cloudflare Pages ל-hosting סטטי חינמי.
- כתובת `*.pages.dev` בשלב הראשון, ללא רכישת domain.
- Cloudflare Web Analytics למדידה בסיסית אם מופעלת.

אין צורך ב-backend לצורך הפרסום הראשוני.

## 8. Monetization עתידי

פרסומות אינן חלק מה-MVP הנוכחי. אל תוסיף AdSense/SDK פרסומי בלי בקשה מפורשת. כאשר יגיע הזמן, יש לבחון UX, פרטיות, consent ודרישות מדיניות לפני שילוב פרסום.

## 9. סגנון קוד ושינויים

- העדף שינויים קטנים, ברורים ובדוקים.
- אל תכתוב מחדש את כל האפליקציה ללא צורך.
- אל תסיר פיצ'ר קיים רק כדי לפשט implementation.
- שמור על אפס build dependencies אם אפשר; הפרויקט נועד להישאר קל להפצה.
- הימנע משימוש בספריות חיצוניות אם ניתן לבצע את המשימה בצורה נקייה ב-vanilla HTML/CSS/JS.
