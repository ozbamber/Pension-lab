# PR2 whole-product audit — 2026-08-31

## Scope and method

This audit covers the complete PR2 application and release path on `codex/pr2-interactive-simulator`: projection math, simulator state, report review, browser persistence and privacy, Hebrew RTL UI, keyboard and assistive semantics, responsive behavior, generated standalone output, repository documentation, and Cloudflare Pages release readiness. Three independent read-only reviews were run for math/state/privacy, UI/accessibility, and repository/release concerns, followed by focused regressions and full release-gate testing.

`app/` remains the only application source. The extraction architecture, pension-report parser, Dataset v2 annotations, OCR routing, and source-identity rules were intentionally left unchanged from reviewed PR1 safety SHA `f7978fe1a15c8e2f738ec0de629e77ff736ceabb`.

## Resolved findings

| Severity | Area | Finding | Resolution and evidence |
| --- | --- | --- | --- |
| P1 | Privacy | Session persistence removed contribution-row `rawText` but could retain raw PDF/OCR fragments nested elsewhere under report evidence; an older v1 session could keep those fragments indefinitely after reload. | Added recursive sensitive-field removal before every report-session write and a load-time migration that rewrites only sessions containing legacy sensitive keys. Browser regressions plant nested and legacy sentinels and verify neither forbidden keys nor text remain in `sessionStorage`. |
| P1 | Financial display | `null` money, percent, severance, and confidence values were coerced to zero, presenting missing evidence as a real `₪0` or `0%`. | Formatting and row rendering now distinguish missing values with an em dash. Chromium coverage verifies a missing severance and confidence. |
| P1 | Simulator math | A zero contribution baseline could expand the control below zero and generate a negative selected monthly contribution before the engine clamp. | Non-negative tracks are floored at zero and the selected contribution is explicitly non-negative; deterministic regression covers the zero baseline. |
| P1 | Accessibility | The native range value exposed an internal 0–10000 position instead of the visible financial percentage. Assistive technology could announce a value such as 5100 rather than 7.1%. | Range min/max/value now use the actual percent domain. A numeric native step is derived so the exact report baseline and endpoints remain valid; native increment/decrement are monotonic, while keyboard scenario steps remain explicit. Browser coverage verifies native value, ARIA value/text, validity, and both native directions. |
| P2 | Input safety | `null`, blank, booleans, arrays, numeric-looking strings, `NaN`, or infinite values could become confirmed zero/minimum or leak invalid state into controls and CSS. Malformed restored objects/rows could also crash the application. | Strict primitive-number parsing rejects absent/coerced/non-finite inputs. Restored state is normalized to safe object shapes, invalid array entries are removed, and corrupt financial values return to review rather than projection. |
| P2 | Projection safety | Blank required values were accepted as zero; saved horizons could be fractional, excessive, blank, or render an empty forecast. | `projectBaseline()` now requires confirmed numeric fields and an integer horizon from 1 to 80. Invalid restored horizons return to the years step. |
| P2 | Restored navigation | A fractional or coerced saved `flowStep` could hide every product section. | Restored steps now use a strict primitive-number allowlist (`2`, `3`, or `4`); malformed values return to visible review. |
| P2 | Numeric overflow | Extremely large but finite balances or contributions could overflow the projection and render em dashes for `NaN` results. | The engine rejects any projection or snapshot with a non-finite numeric result, and the UI keeps the user in the input flow with an announced error. |
| P2 | Fee validation | A restored fee above the review limit could bypass review, while the engine silently clamped it to a different value. | `projectBaseline()` now enforces the same 0%–20% boundary as review; an out-of-range session cannot restore a forecast. |
| P2 | Explorer engine API | `retirementAgeSeries()` changed retirement age but retained an inherited explicit horizon, producing identical projections for different ages. | The explicit horizon and `monthsUntilRetirement` are recomputed for every requested age; regression verifies increasing results. |
| P2 | Career breaks | Overlapping breaks were resolved according to array order. | Overlap is now rejected before projection, independent of input order. |
| P2 | Assumption defaults | Optional `null` assumptions became zero and a zero coefficient appeared in metadata while the engine divided by an implicit fallback. | Missing assumptions use the documented defaults; the coefficient is normalized consistently to at least 1 with 200 as fallback. Explicit zero return/inflation remain valid. |
| P2 | Contribution provenance | An implausible contribution-to-reported-salary ratio could create an absurd percentage control. | Ratios outside 0%–100% fail safely to the amount-only contribution control; no salary or rate is invented. |
| P2 | Review UX | Validation did not expose `aria-invalid`, alert semantics, or focus the first failure; editing one field cleared unrelated errors. | Errors are field-scoped, announced, and focus the first invalid input. Missing optional salary is explicitly labeled as an amount fallback rather than a required confirmation. |
| P2 | Provenance labels | Deleting a previously corrected value could continue to show “manually corrected,” and fee status could hide a remaining missing fee. | Missing evidence now takes precedence and correction markers are removed per field. The combined fee source is recalculated from both values. |
| P2 | Keyboard/focus | Forecast completion and information panels had inconsistent focus return; Enter on the years field did nothing. | Forecast heading is focusable and receives focus after calculation; Enter calculates; information close/Escape returns focus to its trigger. |
| P2 | Flow focus | Back/edit/extraction transitions could leave focus inside a section that had just become hidden. | Every user-driven step transition now has an explicit visible focus target: upload/review headings, years input, forecast heading, routing notice, or continue action. |
| P2 | RTL output | Manually concatenated `+`/`-` currency strings could reorder under bidirectional text. | Signed deltas now use Hebrew `Intl.NumberFormat` with `signDisplay: "always"`. |
| P2 | Non-color status | Central/moderate/extreme slider status was only visually differentiated by track color and hidden explanatory text. | Each control now shows a compact textual status badge in addition to the detailed accessible description. |
| P2 | Same-file retry | Returning to upload did not clear the file input, so selecting the same report again might not fire a change event. | The input and visible file status are cleared when returning to upload. |
| P2 | Hosting correctness | Without a top-level 404 document, Cloudflare Pages treated unknown assets as the application shell with HTTP 200, masking broken asset paths. | Added a branded Hebrew `404.html`; live release verification must assert both status and MIME/content. |
| P2 | Build correctness | Adding a cache-busting query to `styles.css` broke standalone generation because the build matched only an unversioned stylesheet URL. | Standalone generation now accepts the same optional query suffix already supported for scripts; generated-artifact browser coverage passes. |
| P2 | Hosting hardening | The static site sent no repository-defined security headers. | Added `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, and restrictive `Permissions-Policy` headers. |
| P3 | Runtime reproducibility | Documentation required Node 22 but the repository did not pin or declare it. | Added `.nvmrc` and `package.json` engine metadata. |
| P3 | Documentation accuracy | Third-party notices said OCR loaded after a payslip, although the production flow is pension-report-only. | Corrected the notice and added an exact-SHA release/rollback runbook. |
| P3 | Visual accessibility | Progress text, tick labels, and keyboard focus outlines had low contrast. | Increased text/tick contrast and made the focus outline darker and more visible. |

## Release blockers found before this audit

- The canonical production site was still serving the older `origin/main` application and did not contain PR2 or the synthetic demo route.
- Missing deployment assets returned a misleading HTML 200 fallback.
- There was no exact-SHA preview/production runbook or explicit live asset-integrity check.

All three blockers were closed: the final artifact passed the complete release gate, then the same bytes were verified on immutable Preview deployment `e63bc172-95fa-498e-a212-cd1e829ed637` and Production deployment `baeea5ab-faf0-4cd0-ae6e-725d5a894feb`, including the canonical URL. Exact evidence is recorded in `docs/QA.md`.

## Open limitations and recommended follow-up

| Priority | Limitation | Recommendation |
| --- | --- | --- |
| P1 product-quality | Image-only pension-report automatic coverage remains **1/8 (12.5%)** in the existing corpus. This audit does not claim broad real-world OCR coverage. | Keep image-only documents fail-closed/review-heavy and expand independent, consented, de-identified evaluation coverage before making accuracy claims. |
| P2 governance | `AGENTS.md` lists saved scenarios, retirement-age Explorer, career breaks, and other advanced controls as features that must not break, while the current PR1/PR2 product documentation explicitly defers or removes them from the running UI. | Resolve the product contract in a separate owner decision; do not silently reintroduce or delete capabilities in this release. |
| P2 release governance | No hosted CI status check or protected-branch rule was verified. | Add an owner-approved GitHub workflow and branch protection after the current release; keep exact-SHA local and live evidence meanwhile. |
| P2 accessibility | Automated Chromium covers semantics, focus, keyboard use, 390px layout, and overflow, but not a human NVDA/JAWS/VoiceOver session or Safari/Firefox behavior. | Run a manual screen-reader pass and cross-browser matrix before describing the product as fully conformant. |
| P2 security | A strict CSP is not enabled because the distributed standalone HTML intentionally inlines scripts and styles. | Choose a deployment-only CSP strategy or generate hashes/nonces without breaking the standalone artifact. |
| P3 product scope | Taxes, benefit eligibility, provider-specific rules, stochastic outcomes, personalized recommendations, and synchronized accounts remain outside the current model. | Keep the planning-tool disclaimer and use progressive disclosure if these areas are later added. |

## Acceptance criteria

Final acceptance requires every command and live check recorded in `docs/QA.md` to pass. Any omitted check must be marked as not run; a successful Cloudflare upload alone is not production acceptance.
